## Teaching decisions

Open with an unexplained collected value and the unsupported proposal to remove access. Name the uncertainty before diagnosing it. Teach source/object identification and the two collection purposes, then complete the scope/linkage/content correction before competing causes and retirement variants.

Remove fictional employee/application biography, employee number and arbitrary account/group/license IDs. Cases Production retains environment context. case-reviewers and case-reviewers-v2 preserve exact key comparison and replacement uncertainty. Monthly Reviewers and Old Exporters retain the distinct unheld-existing versus confirmed-retired cases. standard-edit/standard-view preserve the license identity/capability comparison.

The main same-day UTC observations retain 09:00 account collection, 09:05 successful CurrentTeams-only definition collection and 09:10 native LegacyTeams existence. Explicit stability excludes a container move, changed key/membership/permission or changed work need during investigation. Matching source/type/schema values are separately verified, so read scope explains this omission rather than assumed matching failure.

The approved scope correction returns the right definition and vague Support access text. Subsequent native meaning, accepted ownership and controlled description maintenance resolve the second problem. Native access remains unchanged. Broader scope acceptance requires population checks; one selected object is not represented as sufficient proof of the whole expansion.

Two diagrams explain separate evidence paths and human scoped correction. Two tables compare observation limits and cause-specific closing evidence. Eight original assessment purposes and the different-system license transfer remain. Counts describe this lesson, not a fixed layout.

Source deletion/catalog synchronization, the account-only-created exception and type deletion are taught as separate mechanisms, without an invented cleanup API or authorization to delete native objects.
