## Editorial decisions

The opening now explains the access-management problem directly. It distinguishes working accounts, missing required permissions and retained unjustified permissions without a fictional employee's assignment providing the narrative continuity.

Devi, employee 11001, Finance biography, and the invented uppercase permission identifiers are removed from the current text. Minimal hypothetical labels Read invoices and Release payments remain only to distinguish two native capabilities and make the delivery requirement verifiable. No new account key, company name or product-specific permission default is invented.

The authoring standard sets coverage and accuracy checks, not a section sequence. This lesson needs one decision/delivery diagram and one evidence-comparison table. The original distributed-information table becomes connected prose explaining each information holder and why no single record answers the whole question. The diagram is a new, narrow editable text asset; earlier diagram derivatives remain explicitly historical.

Four checkpoint purposes and the independent support/export transfer are retained because they test distinct original understandings, not because the course requires four cases. Prompts precede their worked reasoning. No learner-facing course-design promises, source references, or revision metadata interrupt the explanation.

## Assessment intent and accepted reasoning

| Check | Understanding and evidence expected | Misconception exposed |
|---|---|---|
| Application has no error | Establish continuing approved need; if removal required, choose supported action and verify result; a legitimate cross-department need can remain | Correct technical enforcement proves appropriate access |
| Approval plus rejected operation | Decision exists; inspect exact attempted operation/account/rejection, relevant integration authority and current target state; repair depends on proven cause | Repeating business approval repairs technical delivery |
| Imported file, no fulfillment owner | Visibility is limited by file scope/freshness; delivery requires supported mechanism, assigned work, tracking and checks | Importing accounts supplies a complete change service |
| Limited review scope | Included items support bounded conclusions; obtain excluded system's evidence without assuming either misuse or safety | Review completion proves the whole enterprise correct |
| Support/export transfer | Connect identity/account ownership, native capabilities, authority, supported automatic/owned manual delivery and team-change/removal checks; reliable automatic assignment is an acceptable alternative | Account creation alone addresses governance or every application supports automated changes |
