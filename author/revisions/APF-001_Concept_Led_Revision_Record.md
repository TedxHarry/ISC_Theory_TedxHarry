## Teaching decisions

Begin with the real task and its permission dependency: assigned-unit reading plus draft entry, with payment release excluded. Explain a named reusable bundle through that need rather than a definition alone. Native objects, represented references, source boundary and accepted ownership are connected before selection and delivery.

Remove fictional employee/application biography, employee number and arbitrary account/group IDs. Invoices Production retains source/environment context; meaningful invoice-readers/invoice-draft-entry values identify referenced native access without pretending to be ISC API IDs. The target is the correctly associated employee's only existing account, enabled with successful sign-in.

Explain definition, assignment mechanism, enablement, requestability, processing and provisioning before relying on them in the request trace. The main example is standing access, with no account creation, separate activation or automatic role/lifecycle requirement.

Preserve 10:00 definition,10:10 approval,10:12 rejected write and10:15 unchanged Readers/denied draft evidence. Add explicit hypothetical10:05 applied configuration/unchanged partial set so saving is not silently treated as application or selection. The permission correction/recovery and selected native success remain hypothetical observations. No other membership/policy/relevant account-condition change or payment-release route is supplied.

Finish the complete rejected-delivery/recovery case before the independent full-set detection explanation. Detection is not a second compulsory request stage, grant-origin proof or rule to finish incomplete access.

Two diagrams separate bundle references/native membership and configured grant/detection responsibilities. One table compares evidence limits. Eight original question purposes and permission/license transfer remain. Counts describe the subject's needs, not a fixed template.

Detailed profile grouping/configuration/detection/change/removal mechanics remain for their own lessons. Necessary source, assignment-origin, multiple-account and overlapping-removal boundaries remain self-contained.
