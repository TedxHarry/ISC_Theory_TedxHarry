The main rule uses direct permissions, no alternate export grant, an enabled existing account and per-operation current permission checks. ## Technical review and applicability

Claim-bearing sections were checked October 25, 2026. The intended/recorded/effective distinction, gap diagnosis and closure guidance are author-developed teaching/operating models, not named ISC states or platform-mandated workflows.

The supported write, target rejection, manual correction, collected observation and protected-operation check remain distinct. No assumption is made that every change triggers immediate aggregation, that Search refresh is instantaneous, or that identity processing validates provisioning.

The assignment meaning is introduced before manual correction depends on checking continuing requirements. The refresh discussion deepens the baseline's warning with the documented requested-entitlement reprovisioning case. That specific grant origin isn't generalized to all access. Aggregation remains a read; any resulting restoration is a separate write whose target result matters.

The later correction doesn't rewrite the failed activity. Current correctness doesn't prove the business deadline was met or real business data wasn't exported. The lesson preserves a verified timeline and any uncertain exposure interval without manufacturing exact continuous-use evidence.

Search GMT-query/browser-display behavior and change-dependent synchronization were reread in the FAQ. No fixed Search-delay target or retention period is taught. Microsoft material supports checking application-owned session behavior, not universal Microsoft commands or lifetime values. OWASP supports trusted per-request enforcement, not undocumented ISC internals.

No tenant, connector write, manual target edit, Search query or application authorization test was executed. Current labels, time sequence and results remain hypothetical. Current source branding includes Human Fabric / Identity Services; course ISC naming does not imply every navigable capability is licensed or universally available. IdentityIQ behavior isn't used to define ISC.

## Assessment reasoning

| Prompt | Expected reasoning and acceptable alternatives | Misconception exposed |
|---|---|---|
| Newer screenshot, older collected observation | Inspect the exact operation and current target; choose delivery correction or observation maintenance according to the evidence | Opening a screen after removal proves it contains post-removal data |
| Successful delivery of reading-plus-export against reading-only policy | Inspect the shared profile against the approved requirement, assess affected users and coordinate controlled correction | Matching data and successful execution establish appropriate access |
| Empty Search result, present target export | Confirm ownership/identity association, collection and query scope, then synchronization; don't add another grant | Missing visibility proves absence or requires more access |
| Direct export absent, operation still succeeds | Direct removal and unmet effective restriction can coexist; examine alternative grants, session and actual account without assuming the cause | Any continued use means that exact removal failed, or one removed path proves full restriction |
| Two-account portal | Address both accounts, ownership, alternate grants/sessions, collection and authorization-specific evidence; use safe data and preserve reading. Parallel or different ordering can work if all gaps are covered | One account plus a service failure proves a person-wide restriction |
| Independent teach-back | Connect approved requirement, types of ISC records, scope/time and native behavior; explain how the next action addresses a particular gap | Three teaching views are product status fields or a command to make screens match |
